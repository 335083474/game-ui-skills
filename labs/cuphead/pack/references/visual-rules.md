# Visual rules

## Visual grammar

- Tone: Bold, elastic, theatrical, and print-inspired.
- Motifs: thick black keylines, cream stock, limited spot reds and greens, scalloped bursts, two-tone print registration.
- Keep the scene or story image open; controls should frame the action rather than bury it beneath repeated cards.
- Give the primary action one unmistakable selected state. Pair color with shape, label, and focus treatment.
- Titles may use the display face. Body, controls, costs, and state labels use the system sans face from tokens.json.
- Keep short copy lines and generous separation between action controls. At 320 CSS px, reflow instead of clipping.
- Use motion only for selection, reveal, or commit. Respect prefers-reduced-motion.
- The generated art is an inspiration plate or reusable crop, not an interface screenshot or a universal background.

## Palette and type

See tokens.json for the complete palette and dimensions. Keep text on an opaque surface with strong contrast. Reserve the accent for selection and key confirmations; never use it as the only state signal. System fonts are chosen to avoid unlicensed embedded faces.

## Interaction silhouette

Use thick black keylines, cream stock, limited spot reds and greens, scalloped bursts, two-tone print registration as edge vocabulary, not as a replacement for interaction affordances. Focus is always visible, buttons retain real semantic labels, and disabled reasons are adjacent and announced. Treat hover as optional enhancement rather than the only signal.

## Avoid

a modern card dashboard, exact cup-headed or kettle characters, copied bosses, excessive fake film scratches, low-contrast yellow text
