# Visual rules

## Windows, color, and daily life

Set the main text inside thick, rounded black-and-white windows. Let the scene carry bright, unexpected color while the control surfaces remain legible. Keep ordinary objects and status labels concrete; a strange background should not make item names cryptic.

Use violet, cyan, acid green, pink, and orange as small highlights against a dark window. Always pair a state color with a word, outline, or icon. Avoid glossy modern panels, hairline borders, and a sober military-console tone.

## Rolling HP and combat state

Show HP and PP with explicit labels. When HP is shown rolling down, include a stable current-value label and a readable sequence or progress cue; do not fake an actual game calculation. Separate selection, target, and action confirmation.

Goods and commands should have broad rows, simple names, and an obvious selected outline. Local specimen controls update only nearby preview copy.

## Type, input, and layout

Use a system monospace for short labels and counts, with a readable system serif reserved for the specimen heading. Do not load a remote font. Keep four party members readable as rows that stack cleanly below 620px.

Use semantic controls, visible keyboard focus, at least 44px touch targets, and reduced-motion support. Keep psychedelic marks behind an opaque window or outside the text area.
