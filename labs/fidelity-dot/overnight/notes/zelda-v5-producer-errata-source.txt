2. 背景重建入口更正
已直接核对上述 ZIP 的目录和 build_assets.py。
ZIP 内没有以下两个脚本：
sources/background/generate_background.py
sources/background/render_from_matrix.py

撤回 README.md、SOURCES.md、SKILL.md 及其他随包文档中将这两个路径或“可选背景重置生成器”描述为 v5 可用入口的文字。它们不是此冻结 v5 的可执行功能；不应从旧包补入后仍称为同一冻结版本。

此 v5 唯一随包、受支持的背景重建入口是根目录 build_assets.py。它直接读取当前背景矩阵和调色板，不重新推断地形，不调用缺失的重置生成器，也不覆写这两个输入 JSON。

3. 实际命令、输入与输出
需要已可用的 Python 3 和 Pillow。脚本以自身所在目录为根目录，并显式以 UTF-8 读取 JSON；不依赖调用者的当前工作目录，也不要求系统编码或环境变量改为 UTF-8。

Windows 命令示例（将 C:\zelda-skill-v5 替换为实际解压目录的绝对路径）：
python "C:\zelda-skill-v5\build_assets.py"

macOS/Linux 命令示例（替换为实际绝对路径）：
python "/absolute/path/to/zelda-skill-v5/build_assets.py"

当前读取的输入：
- sources/background/palette.json
- sources/background/map_indices.json
- sources/sprites/palette.json
- sources/sprites/sprite_grids.json
- sources/panels.json

当前写入或替换的输出：
- components/background_native.png（256×224）
- components/sprite_<名称>_native.png（当前 29 个独立组件）
- components/panel_<标识>_native.png（当前 5 个面板）

因此，即使只改背景，运行该脚本也会重新生成精灵和面板的原生 PNG。它不生成 4 倍图、不重建字体、不更新 JSON 的浏览器绑定，也不生成浏览器截图。重建后刷新页面以加载更新的 PNG。render_preview.py 是另一个离线初始状态预览入口，不是替代的背景源重建入口；离线渲染不证明浏览器交互通过。
