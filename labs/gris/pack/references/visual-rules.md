# Visual rules

## Paper, architecture, and pigment

Use spacious paper-white fields with fine charcoal architectural lines. Let muted watercolor blooms gather near edges, steps, arches, and chapter markers. Keep a large quiet area around labels. The generated plate is scenery guidance, not a texture to place beneath dense copy.

Color can suggest narrative progression. Keep the mapping consistent within the target game, but pair every color state with a text label, marker shape, or position. Do not make color the only signal for availability or collection.

## Shape and hierarchy

Prefer a delicate path, an architectural threshold, and a small memory fragment over repeated panels. Chapter selection may be arranged along an arc or stepped path, but its keyboard order must remain linear and understandable. Pause should show only the few needed choices and preserve the scene behind it.

Use typography from tokens.json. System serif can carry short chapter headings; local sans is clearer for controls and explanatory text. No remote font or downloaded texture is required.

## State and accessibility

A selected chapter is a preview until Enter chapter is activated. A memory marked found is synthetic example data unless wired to a real save. Opening and closing it are reversible view actions. Keep focus visible against both pale paper and dark linework, use semantic buttons, and announce state changes in a live status region.

Support keyboard and pointer input with the same order. Keep touch targets at least 44 CSS pixels. Under reduced motion, remove drifting wash and decorative transitions while retaining still visual state markers.
