# Usage

Use this package when an original first-person traversal UI needs architectural clarity and a precise visual route language.

1. Read visual-rules.md and tokens.json, then select the relevant pattern in screen-patterns.md.
2. Treat style-board.png as original generated mood context, not a game screenshot.
3. Give the map, mission brief, and movement cue different information roles. Keep normal-play guidance small and keep long mission details on a separate brief surface.
4. Label every route, duration, objective, control, and cue response as synthetic where shown. Do not reuse original characters, game captures, or exact level geometry.
5. Use semantic controls, visible keyboard focus, explicit confirm/cancel, responsive layout, and reduced-motion support.

Open assets/components/index.html locally to view the DOM/CSS specimens. Its actions only change temporary page state; the shown demo key is not an official game mapping.
