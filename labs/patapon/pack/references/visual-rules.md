# Visual rules

## Shape and rhythm
- Use bold solid silhouettes built from circles, diamonds, triangles, bars, and clear cutouts.
- Put a rhythmic beat pattern in spacing and repeated marks, not noisy animation.
- Keep the palette to one strong field and a small number of flat signal colors. No gradient glow or texture is required.
- Pair every command glyph with readable text. The beat timing window must be described in accessible text as well as visualized.
- Use repeated shape and role label for unit identity. Do not use single-eye mascot silhouettes or recognizable source-game creatures.
- Rhythm timing feedback should remain visible after the active beat and be announced without flooding a screen reader.
- Formation, route, and command selection must work with pointer and keyboard.

## Layout and state
Use tokens.json. Give the current beat the strongest visual emphasis; keep future beats smaller and past beats visibly completed. Route costs and squad counts stay textual. At small widths, wrap unit totems and move optional detail behind a labeled disclosure.
